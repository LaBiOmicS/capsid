# 🧬 Capsid

## ⚡ Why Capsid?

Bioinformatics containers have historically suffered from slow build times, giant image sizes (often 1–2 GB), broken dependency solvers, mutable package channels, and lack of security isolation (running as root).

**Capsid** rethinks scientific containerization from first principles:

| Dimension | Legacy BioContainers | **Capsid** |
| :--- | :--- | :--- |
| **Python Tools** (`cutadapt`, `scanpy`, `snakemake`) | Re-packaged in Conda; slow solver, bloated layers (>1 GB) | Direct from PyPI via **`uv`**; sub-second install, **185 MB** |
| **C/C++/Java Tools** (`bwa`, `samtools`, `gatk`) | Heavy `conda-build` Python stack, giant `conda-meta` caches | Ultra-fast **Pixi / Rattler** (pure Rust) multi-stage |
| **Security** | Runs as `root` (UID 0), no process init | **Hardened by default**: unprivileged user (`bio:1000`), **Tini** PID 1 |
| **Container Size** | 600 MB – 1.5 GB | **75% to 88% smaller** (typically 180–210 MB OCI, ~47 MB SIF) |
| **HPC / Apptainer** | Asynchronous server-side conversion | **Native instant SIF export** via `capsid build --apptainer` |
| **Workflow Engines** | Broken signal handling on job cancel | **Tini signal forwarding**: zero zombie processes on Nextflow / Slurm |

## 🛡️ Security by Default

Every container generated by Capsid conforms to the highest container hardening standards:

1. **Non-Root Execution (`bio:1000`)**: Containers strictly execute under unprivileged user `bio` (UID 1000, GID 1000) with `$HOME=/home/bio`.
2. **PID 1 Signal Management (`tini`)**: Containers use `tini` as `ENTRYPOINT ["/usr/bin/tini", "--"]`. Child processes and multithreaded bioinformatic tools receive `SIGTERM`/`SIGINT` immediately when pipelines (Nextflow, Snakemake, Slurm) cancel tasks.
3. **Root-Owned Tool Prefixes**: Binary prefixes (`/opt/venv`, `/opt/conda-env`, `/opt/<tool>`) are owned by root and made world-readable/executable (`chmod -R a+rX`), so the `bio` user can run but not modify them. No global `LD_LIBRARY_PATH` is set (source builds use RPATH).
4. **Secure Scratch Space**: `/tmp` is configured with POSIX sticky-bit permissions (`1777`).
5. **Reproducible Builds**: every base/builder image is pinned by `@sha256` digest; apt resolves against a fixed [snapshot.debian.org](https://snapshot.debian.org) timestamp; conda/PyPI closures come from committed lockfiles (`pixi install --locked`, `uv pip install --require-hashes`); source archives are verified with `sha256sum -c`. The resolved set is also embedded as `/etc/capsid/pixi.lock` / `requirements.lock`. See [Reproducible Builds](#-reproducible-builds-capsid-lock).
6. **OCI Standardization**: Complete OpenContainers labels for provenance, versioning, license, and vendor tracking.

## 🚀 Quick Start

### 1. Installation

Capsid is managed with [uv](https://docs.astral.sh/uv/):

```bash
cd capsid
uv tool install --editable .
```

Verify installation:
```bash
capsid --help
```

---

### 2. Scaffold a Recipe

Scaffold a recipe in seconds from PyPI, Bioconda, or GitHub:

```bash
# Python tool from PyPI (uses Astral uv)
capsid init pypi:scanpy

# Legacy tool from Bioconda (modernized to Pixi Rust)
capsid init bioconda:samtools

# Tool from GitHub repository
capsid init https://github.com/lh3/minimap2
```

---

### 3. Inspect Generated Dockerfile

See the hardened multi-stage Dockerfile without building:

```bash
capsid dockerfile recipes/bwa/recipe.yaml
```

---

### 4. Lock Dependencies

```bash
# Writes pixi.lock / requirements.lock next to recipe.yaml (commit them)
capsid lock recipes/bwa/0.7.19/recipe.yaml
capsid lock stacks/qc-stack.yaml   # -> stacks/qc-stack.pixi.lock, qc-stack.requirements.lock
```

---

### 5. Build Containers (Docker + Apptainer SIF)

```bash
# Build OCI image and run automated tests
capsid build recipes/bwa/recipe.yaml

# Build OCI image AND native Apptainer .sif for HPC
capsid build --apptainer recipes/bwa/recipe.yaml
```

---

### 6. Automated Verification Test

```bash
capsid test recipes/bwa/recipe.yaml
```

---

### 7. Generate Catalog Index

Generate `catalog.json` and view indexed tools:

```bash
capsid catalog
```

## 🔒 Reproducible Builds (`capsid lock`)

| Layer | Pinned by | Notes |
| :--- | :--- | :--- |
| Base & builder images | `@sha256` digest | `debian:bookworm-slim`, `python:3.X-slim-bookworm`, pixi, uv |
| apt packages | `snapshot.debian.org/<timestamp>` | Default images only; `build.apt_snapshot: latest` disables, a custom `base_image` is left untouched |
| Conda packages | `pixi.lock` (all recipe `platforms`) | Generated by the same pinned pixi image used in the build |
| PyPI packages | `requirements.lock` with hashes | `uv pip compile --universal --generate-hashes`, run inside the pinned Python image |
| Source archives | `build.sha256` | Builds without a checksum are refused |
| Timestamps | `SOURCE_DATE_EPOCH` | Passed to BuildKit; apt/dpkg logs are removed |

Locked recipes rebuild **bit-for-bit** (identical OCI manifest digest) with BuildKit's timestamp rewriting:

```bash
docker buildx build --no-cache --build-arg SOURCE_DATE_EPOCH=1700000000 \
  --output type=oci,dest=bwa.tar,rewrite-timestamp=true .capsid-build/bwa
```

`capsid build --push` (and `capsid stack build --push`) publishes this way: only after the local image passes its tests, it rebuilds for every platform in the recipe (`platforms`, or the platforms shared by all stack components) with `docker buildx build --output type=image,push=true,unpack=false,rewrite-timestamp=true --provenance=false` (or `podman build --manifest --rewrite-timestamp` + `podman manifest push --all`). Republishing an unchanged locked recipe pushes the same digest. Cross-platform builds need QEMU/binfmt or native builders.

Without a lockfile the build still works (the solver runs at build time) and `capsid lint` reports `W014_MISSING_LOCKFILE`.
Bump the image digests and `DEFAULT_APT_SNAPSHOT` together (in `builders/dockerfile_gen.py`) to pick up security updates: `python scripts/bump_pins.py` re-resolves every pinned tag (including the `# syntax=` Dockerfile frontend) and sets the snapshot to today; `--check` only reports. The weekly `bump-pins` workflow runs it, then the unit tests and locked smoke builds (`tests/smoke/`), and opens a PR.

## 🔬 Nextflow & Snakemake Integration (`capsid export`)

Instantly generate workflow modules, rules, and configuration profiles:

```bash
# Export Nextflow DSL2 process module
capsid export nextflow samtools@1.25

# Export Snakemake rule
capsid export snakemake samtools@1.25

# Export universal nextflow.config (supporting Docker, Singularity, Apptainer, and SLURM)
capsid export config --target samtools@1.25

# Export native Apptainer/Singularity .def file
capsid export def samtools@1.25
```

## 📐 Cross-language contract

Everything Capsid generates is specified independently of the Python code, so another
implementation (e.g. a Rust/Wasm core) can be checked against the same artefacts:

| Contract | Where | Checked by |
| :--- | :--- | :--- |
| Recipe / stack format | JSON Schema, `capsid schema` → `capsid-hub/schema/*.schema.json` | hub CI (`capsid schema --check`), editors via `yaml.schemas` |
| Templates | `src/capsid/templates/**/*.j2`, Jinja2 subset shared with minijinja; custom filters `dq` and `shq` (see `templating.py`) | `tests/test_minijinja_compat.py` renders the whole golden set with minijinja |
| Outputs | `tests/golden/expected/`: Dockerfile, `module.nf`, `rule.smk`, `Singularity.def`, `nextflow.config` per hub recipe; Dockerfile per stack; `catalog.json`; schemas | `tests/test_golden.py` (byte for byte) |

Timestamps inside generated files come from `SOURCE_DATE_EPOCH`, never from the clock, so the
outputs are deterministic. Refresh the golden set deliberately and review the diff:
`python scripts/update_golden.py --hub ../capsid-hub`.
